# 简历信息填充助手（Edge / Chrome 扩展）

在本机维护自己的简历信息，打开任意含表单的网页（招聘网站、企业招聘系统、报名表等），
点一下就能把信息填进对应的输入框。

**所有数据只保存在本机浏览器（`chrome.storage.local`），插件不发起任何网络请求。**

## 零、官网与安装包

- 官网源码在 [`docs/`](./docs) 目录，纯静态（HTML + CSS + 原生 JS，无构建步骤），可直接用 GitHub Pages 发布
- 扩展安装包放在 [Releases](https://github.com/Kaz-stein/resume-autofill-extension/releases)，官网上的「下载扩展包」按钮指向最新版本
- 官网自检脚本：`node test-fixture/site-check.mjs`（需要先起一个开了 `--remote-debugging-port=9335` 的干净浏览器），
  检查三档宽度的横向溢出、是否加载外部资源、减少动效下的表现、键盘焦点可见性与配色对比度

发布到 GitHub Pages：**Settings → Pages → Source 选 `Deploy from a branch` →
Branch 选 `main`、目录选 `/docs` → Save**。站点会发布在 `https://<用户名>.github.io/<仓库名>/`，
之后每次推送到 `main` 且改动了 `docs/` 都会自动重新构建。

> 也可以改用 GitHub Actions 发布（`actions/deploy-pages`），但那样需要把 Source 改成
> `GitHub Actions`，且首次启用同样要在设置页点一次，并不会更省事。

## 一、安装

Edge 与 Chrome 步骤一致（都是 Chromium 内核）：

1. 打开 `edge://extensions/`（Chrome 是 `chrome://extensions/`）
2. 打开左下角「开发人员模式」
3. 点「加载解压缩的扩展」，选择本目录（含 `manifest.json` 的那一层）
4. 首次安装会自动打开简历管理页，里面有一份示例简历，改成你自己的信息即可

> 安装后已打开的标签页需要刷新一次，内容脚本才会注入。

## 二、使用

两种触发方式：

- **页面右下角悬浮按钮**「一键填写简历」：可拖动，位置会记住
- **点扩展图标 → 弹窗里的「一键填写当前页面」**

填充完成后，页面右上角出现结果面板，列出：

成功填入的字段（可核对填的内容）、跳过的字段及原因、失败的字段及原因，
并提供「撤销本次填充」把页面还原到填充前。

弹窗里的三个开关：

| 开关 | 作用 |
| --- | --- |
| 只填充空白字段 | 默认开。页面上已有内容就不覆盖，避免冲掉你自己填的东西 |
| 填充后高亮字段 | 默认开。绿色描边 2 秒，方便快速核对 |
| 显示悬浮按钮 | 默认开。关掉后只能用弹窗触发 |

## 四、字段是怎么认出来的

### 1. 收集语义线索

对每个输入框，按可信度加权收集线索：

| 线索 | 权重 |
| --- | --- |
| `autocomplete` 属性（浏览器标准，最可靠） | 6 |
| `<label>`（`for=` 关联 / 包裹式 / 表格前置单元格） | 5 |
| `aria-label` / `aria-labelledby` | 4.5 |
| `placeholder` | 3.5 |
| `name` 属性 | 3.2 |
| `id` | 2.6 |
| 邻近文本（逐层向上找前置文本，覆盖常见表单结构） | 2.5 |
| `title` / `class` | 2.4 / 1.4 |

关键词词典写在 `common/schema.js`，中英混排。
中文按包含匹配，英文按词元边界匹配（先把 `realName` 拆成 `real name` 再比对），
避免 `company` 误匹配 `companySize`。

### 2. 消歧

- **负向关键词一票否决**：本地文本（label / placeholder / name / id 等）命中负向词就直接放弃该字段。
  例如「昵称」不会被填成姓名，「公司规模」不会被填成公司名称。
- **邻近文本只轻降权**：邻近文本常混进相邻字段的标签（「离职时间」旁边就写着「离职原因」），
  一刀切会误杀正确字段，所以这里只扣 2 分。
- **区块语义**：向上 6 层找容器标题（教育经历 / 工作经历 / 项目经历…），
  与字段所属分组一致加分，冲突扣分——这是「毕业时间」和「离职时间」不串位的关键。
- **枚举值佐证**：单选框组的选项里同时出现「男」「女」，基本可以确定这就是性别字段，加 4 分。

低于 3 分的候选一律不填（宁可不填，也不乱填）。

### 3. 多条经历怎么对应

页面上按文档顺序出现的第 1 个「学校」填第 1 条教育经历，第 2 个填第 2 条，
最多向页面提供 3 条（`RA.MAX_REPEAT_FILL`）。一个语义只填一次。

## 五、填充执行的关键点

### React / Vue 受控组件

直接写 `element.value = x`，框架的 state 不会更新，
表现就是「页面上看着填上了，提交时是空的」。正确做法是走原型上的原生 setter：

```js
const setter = Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set;
setter.call(element, value);
```

然后依次派发 `input` / `change` / `blur` 事件，页面的校验与状态同步逻辑才会跑完。
测试页里的 `#f-email` 就是专门用来验证这一点的模拟受控输入框。

### 其他控件

- `select`：value 精确 → 文本精确 → 文本包含，命中后派发 `change`
- 单选 / 复选框：按 value 与 label 文本匹配后 `click()`（不是改 `checked`）
- 自定义下拉（Ant Design / Element UI 那类）：先输入尝试筛选，再展开面板按文本点选，
  最多等 1.5 秒；失败会如实报告，不会假装成功
- 日期：按 `placeholder` 猜格式，轮番尝试 `2021-06-30`、`2021/06/30`、`2021年6月` 等写法
- 每个字段填完都**回读校验**，不一致就标记失败并说明原因

### 跨 iframe

招聘表单常嵌在 iframe 里。内容脚本 `all_frames: true` 注入所有框架，
由 background 广播、各框架各填各的，再汇总回顶层框架统一显示结果。
跨域 iframe 拿不到 DOM，只能走消息传递。

## 六、已知限制（实测与推演）

1. **真实招聘网站未做验证。** 本轮只在本机模拟表单和真实浏览器行为上测过。
   BOSS 直聘、智联等站点的自定义组件实现各异，命中率需要实际用过才知道。
2. **只能手动输入的日期控件可用**；纯面板选择（必须点日历翻页）的日期组件不会自动点选，
   会跳到下一个字段并在结果面板里标为失败。级联选择器（省 / 市 / 区三级联动）同理。
3. **富文本编辑器**（Quill / 语雀那类 contenteditable）只做简单文本写入，
   复杂编辑器可能不生效。
4. **只填当前可见的字段**。折叠起来或没展开的表单需要先展开再点填充。
5. `host_permissions` 用了 `<all_urls>`，这是「在任意招聘网站都能用」的代价。
   如果只想自用没问题；若要上架商店，审核会重点问这一条，
   可改成在 `options` 里让用户手动授权具体域名。
6. 导入 JSON 只做追加，不覆盖已有简历；清空数据有二次确认，且无法恢复。

### 测试中发现并修掉的 4 个真实缺陷

这些不是演示用的脚手架问题，而是会在真实网站上同样犯错的 bug：

1. **单选按钮组丢成员**：建组时没把第一个 radio 放进组里，导致「性别」组里只有「女」没有「男」，
   永远选不上。修法是建组后立即把当前元素也 push 进组。
2. **负向关键词只扣分不够**：「离职原因」靠着邻近文本仍能凑到 3.5 分（高于阈值 3），
   被误判成「离职时间」并填成「至今」。改成**本地文本命中负向词直接一票否决**，
   邻近文本才用轻降权。
3. **结果汇总过早收尾**：后台固定 3.5 秒就汇总，而顶层框架填 17 个字段要 5 秒以上，
   结果面板漏报、用户以为没填上。改成各框架先「报到」、后台按参与者数量等齐再汇总。
4. **一个字段出错会中断整轮填充**：撤销快照创建在 try 之外。已移进 try 内。

## 八、隐私

- 只写入 `chrome.storage.local`，不联网、不上报、无第三方统计
- 不使用 `eval`，不注入任何远程脚本
- 结果面板里身份证号、紧急联系人电话默认用掩码显示
- 导出 JSON 会走浏览器下载（含明文个人信息，注意别随手发出去）
